# ADR-0019: 대화 길이 알림을 제거하고, 새 세션은 컴포저 메뉴로 노출한다

- **Status**: Accepted
- **Date**: 2026-08-07
- **관련**: `src/components/chat/ChatContent.tsx`, `src/stores/chatStore.session.ts`, [ADR-0012](0012-provider-only-model-selection.md)의 Phase 3 요약(`043f336`)

## Context

채팅 패널 상단에 "대화가 길어졌습니다. 새 세션을 시작하시겠어요?" 배너가 떠 있었습니다. 이 배너는 초기 릴리스(`eb47555`, 2026-01-22)부터 있던 것으로, 조건은 **메시지 개수 30개 이상 + 세션별 dismiss 안 함**이 전부였습니다(`CHAT_LENGTH_THRESHOLD`). 토큰도 요약 상태도 보지 않았습니다.

그로부터 반년 뒤 Phase 3(`043f336`, 2026-07-23)에서 **자동 요약**이 들어왔습니다. `planConversationContext`가 매 전송마다 최근 8~12턴만 원문으로 남기고 나머지를 누적 요약으로 접습니다. 배너를 추가할 때 기존 배너를 정리하지 않아 둘이 그대로 공존하게 됐습니다.

**관측된 결함 셋:**

- **두 배너가 겹칩니다.** 최근 원문 윈도우 상한이 12턴 = 24개 메시지(`conversationContext.ts`)이므로 **25번째 메시지부터 자동 요약이 이미 돌기 시작합니다.** 문제의 배너는 30개에서 뜹니다. 결과적으로 배너가 뜨는 시점엔 압축이 이미 진행 중이고, 바로 아래 Phase 3 배너가 "이전 대화가 요약되어 컨텍스트로 유지됩니다"라고 말합니다. 화면이 동시에 "길어졌으니 새로 시작할래?"와 "알아서 압축하고 있으니 괜찮다"를 말합니다.
- **끌 수가 없습니다.** `summarySuggestionDismissedBySessionId`는 SQLite에 들어가지 않고 메모리에만 있어, hydrate/reset마다 `{}`로 초기화됐습니다. "무시"를 눌러도 앱을 재시작하고 같은 세션을 열면 배너가 되돌아옵니다. 30개를 넘긴 세션을 계속 쓰는 사용자에게는 영구적으로 재출현하는 배너였습니다.
- **트리거가 실제 압력과 무관합니다.** 짧은 메시지 30개는 예산 근처도 못 가고, 문서 덩어리가 붙은 메시지 10개는 훨씬 빨리 압박이 옵니다. 고정 카운트는 무엇도 대리하지 않았습니다.

또한 배너가 권하는 행동(`startNewSessionFromSuggestion`)은 `createSession()`으로 빈 세션을 만들 뿐 맥락을 전혀 옮기지 않습니다. 가볍게 묻는 톤으로 대화 흐름을 통째로 끊는 행동을 권하고 있었습니다.

### 검토한 대안과 버린 이유

- **그대로 둔다.** 위 세 결함이 그대로 남습니다. 특히 "끌 수 없다"는 점 때문에 시간이 갈수록 마모가 누적됩니다.
- **트리거를 똑똑하게 고친다** (토큰 압력이나 요약 발생 횟수 기준으로 교체). 실제로 유용한 신호는 "대화가 길다"가 아니라 **"주제가 바뀌었다"**인데, 주제 전환은 싸게 감지할 방법이 없습니다. 토큰 압력으로 대신하면 그건 이미 자동 요약이 처리하는 축이라 같은 중복이 다시 생깁니다. 측정할 수 없는 것을 근사하려고 새 휴리스틱을 만드는 일이 됩니다.
- **슬래시 명령(`/clear`, `/new`)과 자동완성으로 대체한다.** 이 앱에는 슬래시 명령 체계가 **아예 없습니다** — `sendCurrent`가 입력을 파싱 없이 `sendMessage`로 넘기므로 `/clear`는 그냥 AI에게 전송되는 문자열입니다. 그리고 슬래시 명령은 발견성 도구가 아닙니다: `/`를 쳐볼 생각을 하려면 명령 체계가 있다는 걸 이미 알아야 하므로, 사이드바 `+`를 못 찾는 사용자는 `/`도 안 칩니다. 명령의 값은 **이미 아는 사람의 속도**지 발견성이 아닙니다. 파싱 계층·레지스트리·자동완성 팝업을 새로 만들고 `/`로 시작하는 정상 텍스트(경로, `/2026` 같은 날짜)의 이스케이프 규칙까지 떠안는 비용은 별개입니다.

## Decision

**대화 길이 알림을 제거한다. 컨텍스트 관리는 자동 요약이 전담하고, 사용자에게 수동 조치를 권하지 않는다.**

알림의 판단 기준은 "사용자만 내릴 수 있는 판단을 요구하는가"입니다. 이 배너는 판단 근거를 주지 않고(지금 컨텍스트 압력이 얼마인지, 요약이 무엇을 잃었는지 알려주지 않음), 시스템이 이미 해결한 상태를 두고 수동 조치를 권했습니다.

제거 범위(`ChatContent.tsx` 배너 JSX와 함께 죽는 것들):

- 셀렉터 `useSummarySuggestionState` (`chatStore.selectors.ts`)
- 스토어 메서드 `shouldShowSummarySuggestion` / `dismissSummarySuggestion` / `startNewSessionFromSuggestion` (`chatStore.session.ts`)
- 상태 `summarySuggestionDismissedBySessionId` (초기화 3곳 + `deleteSession`의 정리 코드)
- 상수 `CHAT_LENGTH_THRESHOLD` (`chatStore.types.ts`)와 `chatStore.ts`의 재export
- i18n `chat.longConversationNotice`, `chat.startNewSession`

**Phase 3 요약 배너(`chat.memorySummaryActive`)는 남긴다.** 성격이 다릅니다 — 행동을 요구하지 않고 상태만 알리며, 사용자가 실제로 궁금해할 유일한 지점("요약되면 원본이 날아가나?")에 답합니다.

**대신 새 세션의 발견성을 어포던스로 해결한다.** 기존 경로는 사이드바 탭바의 **아이콘 전용 `+` 버튼**(`UnifiedSidebar.tsx`, 라벨 없이 `title` 툴팁만) 하나뿐이었습니다. 사용자가 이미 여는 컴포저 옵션 메뉴 맨 아래에 구분선과 함께 "새 채팅" 항목을 추가합니다(`ChatContent.tsx:handleNewSessionFromMenu`). 세션이 상한(`MAX_CHAT_SESSIONS` = 5)에 도달하면 조용히 무시하지 않고 경고 토스트를 띄웁니다.

## Consequences

- **얻은 것**: 컨텍스트 관리에 대해 앱이 한 가지 이야기만 합니다. 겹치는 두 배너 중 부정확한 쪽이 사라졌습니다.
- **얻은 것**: 재시작마다 되살아나던 배너가 없어졌습니다. 영속되지 않는 dismiss 상태를 고치는 대신 대상 자체를 지웠으므로, 영속화 코드를 새로 쓰지 않았습니다.
- **얻은 것**: 코드가 순감했습니다(-125/+34). 하드코딩돼 있던 `30`(셀렉터가 상수를 쓰지 않았음)과 UI·테스트 어디서도 쓰지 않던 죽은 스토어 메서드가 이 삭제에 흡수됐습니다.
- **잃은 것 / 감수하는 것**: **긴 대화에서 새 세션을 권하는 넛지가 없어집니다.** 요약은 손실 압축이고 요약 호출 비용도 계속 들기 때문에, 주제가 바뀌었다면 새 세션이 실제로 더 낫습니다. 그 판단을 이제 전적으로 사용자에게 맡깁니다. 되살리려면 이 ADR을 뒤집어야 하며, 되살릴 때는 트리거를 개수가 아닌 다른 것으로 정해야 합니다.
- **감수하는 것**: 발견성 개선이 실제로 효과가 있었는지 측정하지 않습니다. 이 앱에는 사용 분석이 없으므로 "메뉴에 넣었으니 찾을 것"이라는 가정 위에 서 있습니다. 사용자가 여전히 못 찾는다고 하면 다음 후보는 사이드바 `+` 버튼에 라벨을 붙이는 것입니다.
- **따라오는 의무**: 앞으로 채팅 패널에 알림을 추가할 때는 **행동을 요구하는 알림인지 상태만 알리는 알림인지** 먼저 정합니다. 행동을 요구한다면 사용자가 그 판단을 내릴 근거를 같은 자리에서 줘야 합니다. 근거 없이 묻는 알림은 이 ADR이 지운 것과 같은 종류입니다.
