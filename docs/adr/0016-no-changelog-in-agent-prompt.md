# ADR-0016: CLAUDE.md에 변경 이력을 두지 않고, 내용의 종류로 문서를 나눈다

- **Status**: Accepted
- **Date**: 2026-07-30
- **관련**: [ADR-0001](0001-adopt-adr.md)의 "Recent Updates는 그대로 둔다" 조항을 대체합니다(ADR 제도 자체는 유효). `.claude/CLAUDE.md`, `.claude/commands/update-docs.md`

## Context

ADR-0001은 ADR을 도입하면서 `.claude/CLAUDE.md`의 Recent Updates를 **그대로 두기로** 했습니다. 근거는 역할 분리였습니다 — CLAUDE.md는 에이전트가 매 세션 읽는 작업 컨텍스트, ADR은 사람이 필요할 때 찾는 이력 저장소. 중복은 감수하기로 했습니다.

1년이 아니라 하루 만에 그 전제가 깨졌습니다. 2026-07-30 측정값입니다.

| | 토큰(추정) | 로딩 |
|---|---|---|
| `.claude/CLAUDE.md` 전체 | ~16,900 | **매 세션 자동** |
| └ Recent Updates | **~14,800 (87%)** | 매 세션 자동 |
| └ 나머지(개요·명령어·원칙·E2E) | ~2,100 | 매 세션 자동 |

날짜 섹션이 13개, 가장 오래된 것이 2026-04-06입니다. 그중 11개는 ADR 도입(0001) 이전 것이고, 상당수는 소급 ADR(0002–0009)로 근거가 이미 옮겨졌습니다 — **중복이 구조적으로 보장된 상태**였습니다.

문제는 토큰 비용이 아닙니다(캐시됩니다). **낡은 항목이 사라지지 않는다**는 것입니다.

- `Previous (2026-04-28)`은 "GPT-5.4 → GPT-5.5, `aiConfigStore` v8 → v9, `gpt-5.4-mini`는 chat 저비용 옵션으로 유지"를 지시합니다. [ADR-0012](0012-provider-only-model-selection.md)가 프리셋 자체를 폐기하고 v14로 갔으니 **현재 코드와 정면으로 모순**입니다. 위에서 아래로 읽는 에이전트는 상충하는 두 사실을 함께 받습니다.
- 같은 종류의 드리프트가 옆 문서에도 있었습니다 — `architecture.md`가 제거된 `confluence_word_count`를, `patterns.md`가 옮겨진 `src/ai/chat.ts`의 `EXTERNAL_TOOLS` 배열을 설명하고 있었습니다. CLAUDE.md 스스로도 "`src/ai/README.md`는 아직 드리프트 상태다", "`patterns.md:227`에 `runToolCallingLoop`가 남아 있다"고 적어 **드리프트를 문서로 관리**하고 있었습니다.
- `/update-docs` 커맨드는 Recent Updates를 **언급조차 하지 않았습니다.** CLAUDE.md의 역할을 "버전, 명령어, 퀵 레퍼런스"로만 정의해뒀습니다. 이 섹션은 정해진 절차가 아니라 관행으로 자랐습니다.

ADR-0001이 놓친 것은 이것입니다. **CLAUDE.md는 문서가 아니라 프롬프트입니다.** 그래서 판정 기준이 "정확한가"가 아니라 "매 세션 모든 작업에서 행동을 바꾸는가"여야 하는데, 이력은 이 기준을 영구히 통과할 수 없습니다 — 어제 바뀐 것은 오늘 중요하지만 3개월 뒤에도 같은 자리를 차지합니다.

### 검토한 대안과 버린 이유

- **상한을 두고 최근 5개만 남긴다** (각 1줄 + ADR 링크). 버렸습니다. 상한은 append 압력을 못 이깁니다 — 이 섹션이 자란 방식이 정확히 "이번 것만 한 줄 더"였고, 실제로 이 세션에서도 같은 관행으로 6줄이 추가됐습니다. 그리고 남길 값어치가 있는 내용(구현 함정)은 날짜가 아니라 주제로 정렬돼야 합니다.
- **`docs/CHANGELOG.md`로 옮긴다.** 버렸습니다. `git log`와 중복이고, 계획 문서들이 이미 보여준 대로 갱신되지 않는 문서가 하나 더 늘어납니다.
- **항목을 하나씩 검증해 살아있는 것만 이관한다.** 사용자 판단으로 버렸습니다 — 비용 대비 이득이 낮고, 지운 내용은 git에 그대로 남아 있어 필요할 때 꺼낼 수 있습니다.
- **ADR만으로 충분하다** (gotchas 없이). 버렸습니다. ADR README가 스스로 `안 쓴다: 버그 수정, 리팩터링, 구현 세부`, `한 장을 넘기지 않는다`로 정해두었으므로, "이 effect는 ref 할당 effect보다 뒤에 선언해야 한다" 같은 함정은 ADR에 들어갈 자리가 없습니다. 그 집은 `gotchas.md`입니다.

## Decision

**CLAUDE.md에서 변경 이력을 없애고, 내용의 종류로 집을 정한다.** 분류축을 날짜에서 종류로 바꾼다.

| 종류 | 집 |
|------|-----|
| 왜 그렇게 됐나 / 무엇을 버렸나 | `docs/adr/` |
| 다시 밟으면 아픈 구현 함정 | `gotchas.md` — 주제순이라 낡은 항목이 새 항목 옆에서 발각된다 |
| 현재 구조·계약 | `architecture.md` / `patterns.md` — 덧붙이지 말고 **갈아끼운다** |
| 언제 무엇이 바뀌었나 | `git log` — 어느 문서에도 쓰지 않는다 |

- Recent Updates 13개 날짜 섹션(177줄)을 삭제한다. 항목별 검증·이관은 하지 않는다. 내용은 `git show 2f157b2:.claude/CLAUDE.md`에 남는다.
- `.claude/CLAUDE.md`에 "무엇을 어디에 쓰나" 표와 **이력 금지 규칙**, **300줄 상한**을 명시한다.
- `.claude/commands/update-docs.md`에 같은 금지를 "절대 규칙"으로 넣고, 종료 시 `wc -l .claude/CLAUDE.md ≤ 300` 확인을 넣는다. 규칙을 커맨드에 박지 않으면 다음 작업에서 관행이 되살아난다.

## Consequences

- **얻은 것**: 상시 로드되는 프롬프트가 ~16,900 → **~2,448 토큰**(178줄)이 됐습니다. 현재 코드와 모순되는 지시가 프롬프트에서 사라졌습니다. 새 지식의 목적지가 종류별로 하나뿐이라 "어디에 쓰지"를 매번 고민하지 않습니다.
- **잃은 것 / 감수하는 것**:
  - 최근 항목(7/28–7/30)의 구현 세부 중 일부는 ADR·gotchas에 대응 항목이 없을 수 있습니다. **검증 없이 지우기로 한 결정의 대가**이며, 접근 경로는 `git show`뿐입니다.
  - "최근 무슨 작업을 했나"를 프롬프트로 즉시 알 수 없습니다. `git log`를 봐야 합니다 — 그게 원래 그것의 집입니다.
- **따라오는 의무**:
  - 작업 후 남길 지식은 위 표대로 배분합니다. CLAUDE.md에 이력을 쓰고 싶어지면 그 내용은 gotchas나 ADR에 속한 것입니다.
  - 300줄 상한은 자동 검사가 없습니다. `/update-docs`의 마지막 단계에서 사람이 확인합니다.
  - `.claude/handoff.md`와 `docs/dynamic-project-knowledge-fix-plan.md`에 "Recent Updates에 추가" 체크박스가 남아 있습니다. 완료된 세션 기록이라 손대지 않았지만, 그 지시를 따르면 안 됩니다.
