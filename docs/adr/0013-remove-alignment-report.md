# ADR-0013: 정렬 리포트를 제거하고, 영속 정렬은 계측 없이 보류한다

- **Status**: Accepted
- **Date**: 2026-07-30
- **관련**: [ADR-0008](0008-alignment-computed-not-persisted.md)(이 문서가 Consequences의 "의도된 부산물"·"따라오는 의무" 항목을 대체), `src/components/editor/AlignmentView.tsx`

## Context

ADR-0008은 정렬을 저장하지 않기로 하면서, 대신 정렬 뷰 하단에 `정렬 리포트` 버튼을 두었습니다. 목적은 Phase 5(영속 정렬 레이어, 4–6주)를 착수할지 판단할 데이터를 모으는 것이었고, 기준까지 정해져 있었습니다 — `ratio ≥ 0.95`면 불필요, `0.7` 근처면 착수 가치 있음.

2026-07-30 기준으로 이 계측기는 **한 번도 돌지 않았고 수집된 데이터는 0건**입니다. 그 상태로 화면에 남아 있는 결과는 두 가지입니다.

- **번역가에게는 의미 없는 버튼**입니다. 정렬 뷰를 쓰는 사람이 원하는 건 JSONL 한 줄이 아니라 "안 맞는 걸 고치는 것"인데, 리포트는 개발 의사결정용 샘플 수집기입니다. 사용자 화면에 개발자용 계측기가 노출돼 있었습니다.
- 기록만 하고 읽는 곳이 없는 구조는 [ADR-0007](0007-remove-quality-ledger.md)에서 이미 한 번 걷어낸 형태입니다. 품질 장부와 다른 점은 "읽을 사람과 임계값이 정해져 있다"는 것뿐인데, 그 독자가 1년 가까이 나타나지 않았습니다.

계측기로서의 결함도 하나 있습니다. **`ratio`는 "번역에서 문단이 실제로 빠졌다"와 "1:N이라 `alignUnits`가 짝을 못 지었다"를 구분하지 못합니다**(1:N 미지원은 ADR-0008이 감수한 한계). 그래서 숫자가 낮게 나와도 답이 영속 정렬인지, 정렬 알고리즘의 1:N 지원인지, 번역 품질인지 가려주지 못합니다. 애초에 이 지표만으로는 Phase 5 판단이 서지 않았습니다.

## Decision

**정렬 리포트를 제거한다. Phase 5는 계측 없이 계속 보류한다.**

- `src/utils/alignmentReport.ts`, 정렬 뷰 하단 버튼, i18n 3키(`exportReport`/`reportSaved`/`reportFailed`), 해당 E2E 단언을 삭제
- `src/tauri/dialog.ts`의 `pickJsonlExportPath`도 함께 삭제 — 유일한 호출자가 리포트였다. 문서 내보내기는 `pickExportDocumentPath`, `write_text_file`(Rust 커맨드·E2E 목)은 `ExportModal`이 계속 쓰므로 남긴다
- 화면에 남는 정렬 품질 신호는 **하단 요약(총 문단 / 정렬 / 불일치 + 막대)**, `degraded` 경고, `위치를 특정하지 못한 이슈 N건` 세 가지다. 눈으로 보기에 충분하고, 파일로 뽑을 이유는 Phase 5 판단뿐이었다

### 버린 대안

- **리포트를 유지하고 실문서로 몇 건 뽑아본다** — 몇 분이면 되지만, 위에서 적었듯 `ratio` 하나로는 원인이 갈리지 않아 뽑아도 Phase 5 판단이 서지 않는다. 판단이 안 서는 숫자를 위해 사용자 화면에 버튼을 남길 이유가 없다.
- **정렬을 손으로 고치는 UI**(행 병합·드래그) — 고친 결과를 저장해야 의미가 있고, 저장하면 ADR-0008이 피한 함정(틀린 정렬이 데이터로 굳는 것)으로 되돌아간다. 그게 곧 Phase 5다.

## Consequences

- **얻은 것**: 정렬 뷰가 번역가에게 의미 있는 것만 보여줍니다. 죽은 계측 경로 하나가 사라졌습니다.
- **잃은 것**: Phase 5 착수 여부를 숫자로 판단할 경로가 없습니다. **그건 의도된 것입니다** — 판단 근거가 생길 때까지 안 하기로 한 것이고, 근거는 리포트가 아니라 실사용에서 "정렬이 안 맞아서 못 쓰겠다"가 반복될 때 생깁니다.
- **불일치를 만났을 때의 대응은 기존 경로 그대로**입니다. 불일치 행에서 문서 보기로 점프해(`jumpToUnit`) 거기서 고칩니다. 정렬 불일치는 대개 화면의 문제가 아니라 번역이 빠졌거나 합쳐진 **증상**이므로, 고칠 대상은 정렬이 아니라 문서입니다.
- **다음에 이 화면을 손볼 때 후보**: 1:0 행에서 곧바로 그 문단을 번역해 넣는 액션. 기존 선택 재번역 경로를 재사용하므로 영속 정렬과 비교가 안 되게 싸고, ADR-0008의 "저장하지 않는다"와도 충돌하지 않습니다. 아직 결정하지 않았습니다.
