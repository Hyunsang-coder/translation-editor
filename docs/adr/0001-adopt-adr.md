# ADR-0001: ADR을 도입한다

- **Status**: Accepted
- **Date**: 2026-07-29
- **관련**: [docs/INDEX.md](../INDEX.md), [.claude/CLAUDE.md](../../.claude/CLAUDE.md)

## Context

이 저장소에는 결정의 **근거**를 남길 자리가 없었습니다. 지금까지 근거는 세 곳에 흩어져 있습니다:

- `.claude/CLAUDE.md`의 "Recent Updates" — 결정과 그 이유가 산문으로 섞여 있고, 날짜순으로 계속 쌓입니다. 에이전트 컨텍스트용이라 매 세션 전량 로드되며, 오래된 항목도 지울 수 없습니다(왜 그렇게 됐는지가 거기에만 있으므로).
- `docs/*-plan.md` — 착수 전 계획서. 실제로 무엇이 채택됐고 무엇이 폐기됐는지는 계획서를 다 읽어야 알 수 있습니다.
- 커밋 메시지 — 무엇을 바꿨는지는 있지만, **버린 대안**은 없습니다.

증상은 반복적으로 나타났습니다. 이미 폐기하기로 결정한 것(Phase 4-3 세그먼트 인스펙터, 품질 장부)을 되살리자는 제안이 다시 올라오고, 그때마다 "왜 버렸는지"를 CLAUDE.md에서 찾아 다시 설명해야 했습니다.

검토한 대안:

- **아무것도 안 한다** — 결정 이력은 계속 CLAUDE.md에 쌓입니다. 그 파일은 에이전트가 매 세션 통째로 읽는 컨텍스트라, 이력 저장소로 쓰면 토큰만 잠식하고 검색은 안 됩니다. 기각.
- **계획 문서(`*-plan.md`)에 "결정" 절을 추가한다** — 계획 문서는 착수 전에 쓰이고 완료 후 갱신되지 않습니다. 실제로 `docs/` 안에 상태가 어긋난 계획서가 이미 여럿 있습니다. 기각.
- **커밋 메시지 규약을 강화한다** — 검색이 어렵고 링크가 안 되며, 결정이 여러 커밋에 걸치면 어디에 썼는지 알 수 없습니다. 기각.

## Decision

`docs/adr/`에 Michael Nygard 포맷의 ADR을 둔다. 규칙은 [README.md](README.md)에 있고, 핵심은 셋:

1. 되돌리기 비싼 결정만 기록한다 (스키마 변경, 외부 계약 breaking, 기능 폐기, 대안을 버린 선택)
2. **한번 Accepted된 문서는 고치지 않는다.** 뒤집히면 새 ADR을 쓰고 옛것을 `Superseded by`로 표시한다
3. 결정을 담은 PR에 함께 커밋한다

도입 시점에 살아있는 제약 8건을 소급 기록한다 (ADR-0002 ~ 0009). 소급 대상은 "지금도 코드에 제약으로 남아 있는 것"으로 한정하고, 이미 끝난 작업 이력은 옮기지 않는다.

`.claude/CLAUDE.md`의 Recent Updates는 **그대로 둔다.** 그 파일은 에이전트가 매 세션 읽는 작업 컨텍스트이고, ADR은 사람이 필요할 때 찾아보는 이력 저장소로, 역할이 다르다. 소급된 항목에는 `(ADR-000X)` 참조만 붙인다 — 내용 중복은 감수한다.

## Consequences

- **얻은 것**: 폐기 결정에 근거가 생겼습니다. "이거 왜 없어요?"에 링크 하나로 답할 수 있고, 되살리자는 제안이 오면 당시 버린 이유와 대조할 수 있습니다.
- **잃은 것 / 감수하는 것**: CLAUDE.md와 ADR에 같은 내용이 두 벌 존재합니다. 둘이 어긋나면 **ADR이 결정의 근거에 대한 진실**이고, CLAUDE.md는 현재 코드 상태의 요약입니다.
- **따라오는 의무**: 새 ADR을 쓸 때마다 README 목록 표에 한 줄 추가. 결정이 뒤집힐 때 옛 ADR의 Status 갱신을 빠뜨리면 이 제도는 바로 거짓말을 시작합니다.
